# Nigehbaan (نگہبان)

Flood-response prioritization MVP for **CODE//CONNECT'26** (Problem 01: Disaster Response).

> During floods, warnings don't reach everyone. Nigehbaan finds the households most at risk, including ones missing from official lists, and matches scarce boats and shelters to them fairly.

**Status:** Step 0 done (scaffold, data pipeline, map). Scoring, dispatch and the other portals come next.

## Stack

Next.js (App Router) + TypeScript + Tailwind CSS + Leaflet (react-leaflet) + Recharts. No backend: data lives in static JSON under `public/data/`. Deploys on Vercel.

## Setup

```bash
npm install
npm run data     # data/*.csv -> public/data/*.json
npm run dev      # http://localhost:3000
npm run build    # production build
```

## Data

- `data/households.csv`: 150 real OpenStreetMap building locations in Karachi (Malir side) with real terrain height (SRTM), flood history (JRC) and night light (VIIRS). Columns ending in `_est` (people, age, illness, income, etc.) are **modelled estimates from published rates, not real people**. Generated by a Colab notebook (Earth Engine + OpenStreetMap); add it to `data/` for reproducibility.
- `data/shelters.csv`: OSM schools, hospitals, clinics, community centres and mosques. If this file is missing, `npm run data` generates clearly labelled **placeholder** shelters so the app still runs.
- `npm run data` is deterministic. It marks 20% of households (seeded) as `source: "satellite"` (unlisted/hidden) and the rest as `"survey"`. Empty cells become `null`; the app must never crash on them.
